1. Registers a0-a7 hold function arguments. In main's call to printf,
a0 = format string, a1 = 12 (f(8)+1), a2 = 13 ("li a2,13" at 0x24).

2. There is no call to f or g in main. The compiler inlined g into f and
constant-folded f(8)+1 into 12, so main just does "li a1,12" at 0x26.
f also inlines g ("addiw a0,a0,3" instead of calling g).

3. printf is at 0x70e ("jal 70e <printf>" at 0x30).

4. ra = 0x34, the address of the instruction right after the call at 0x30.

5. Output: "HE110 World". 57616 = 0xe110. RISC-V is little-endian, so
i = 0x00646c72 is stored as bytes 72 6c 64 00 = "rld\0".
Big-endian: i would need to be 0x726c6400. 57616 would not change,
because %x prints the numeric value, not the bytes.

6. An unpredictable value: printf reads the 3rd argument from a2,
which the caller never set, so it prints whatever was left in a2.
